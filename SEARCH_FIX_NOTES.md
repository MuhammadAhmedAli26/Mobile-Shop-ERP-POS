# SEARCH ENGINE & ROUTING UPGRADE NOTES (GATES G1 & G2)
**Date:** 2026-10-11  
**Project:** Mobile & Accessories Shop ERP + POS (v3.2 Offline Edition)  
**Port:** 8085 (localhost)  

---

## 1. Hypotheses, Evidence & Verified Root Causes (Gate G1)

### Hypothesis 1: Route Mismatch on Inventory Model URLs
- **Hypothesis**: The search engine creates URLs pointing to `/inventory/models/{product_id}`, but no such route is registered in Bottle.
- **Evidence**:
  - `search.py:90` and `search.py:146` construct `url: f"/inventory/models/{product_id}"`.
  - Inspection of `web_ui.app.routes` revealed only `/inventory` and `/inventory/product/<pid:int>/units`.
  - Calling `GET /inventory/models/1` returns HTTP 404 with raw Bottle error layout.
- **Root Cause**: Missing route handler in `web_ui.py` for `/inventory/models/<pid:int>` and lack of a central URL generation standard between `search.py` and `web_ui.py`.

### Hypothesis 2: POS Input Only Handled Scans, Not Text Search
- **Hypothesis**: `#pos-scan-input` was designed solely as an Enter-driven scanner receiver and lacked an autocomplete/typeahead dropdown for hand-typed product names.
- **Evidence**:
  - `#pos-scan-input` has no `oninput` handler or typeahead dropdown markup.
  - On `Enter`, `handleScanSubmit()` passes the value to `/api/scan-route`.
  - `scanner.universal_scan_route()` treats non-digits as barcodes/SKUs (`BARCODE_OR_SKU`) and looks only in `variants.barcode` or `variants.sku`.
  - Querying `"samsung"` returns `{"success": false, "type": "CODE_NOT_FOUND"}`.
- **Root Cause**: POS lacked a real-time typeahead search dropdown and had no search fallback for typed model/accessory names.

### Hypothesis 3: Artificial Minimum Length Restriction
- **Hypothesis**: Search was deliberately artificially throttled by a 2-character guard in both frontend and backend.
- **Evidence**:
  - `search.py:352`: `if not q or len(q) < 2: return {"query": query_str, "results": {}}`
  - `web_ui.py:285`: `if (q.length < 2) return;`
  - Querying `"a"` returned zero results even with thousands of matching items in DB.
- **Root Cause**: Premature optimization / legacy copy-paste guard that prevented 1-letter instant lookups.

### Hypothesis 4: Raw Bottle Error Layouts
- **Hypothesis**: Unhandled routes and 404/500 errors expose Bottle's default unstyled HTML pages.
- **Evidence**:
  - Missing `@app.error(404)` and `@app.error(500)` in `web_ui.py`.
  - Non-existent URLs return unstyled plain HTML with `<h1>Error: 404 Not Found</h1>`.
- **Root Cause**: Missing application-level error handlers in `web_ui.py`.

## 2. Architecture & Design Specification (Gate G2)

### 2.1 Single Source of Truth URL Map & Router Helper
All internal navigation targets generated by search results or deep links must follow a unified contract:

| Entity | Deep Link Route | Handler Behavior in `web_ui.py` | Fallback if Not Found |
|---|---|---|---|
| **Product Model** | `/inventory/models/<pid:int>` (and `/inventory/models/<pid:int>/`) | Renders Inventory screen with Model Details Modal/Drawer open (showing specs, variants, stock, units, price) | Renders in-app notice: "Model not found" + [Back to Inventory] button |
| **Phone Unit** | `/inventory/models/<pid:int>?unit=<uid:int>` | Same as above, highlighting the specific unit's IMEI and status | Displays model with notice if unit missing |
| **Customer Khata** | `/credit/customer/<cid:int>` | Renders Credit screen with customer row highlighted or opening Khata Ledger | Opens `/credit` with notice |
| **Supplier Ledger** | `/purchasing/supplier/<sid:int>` | Renders Purchasing screen with supplier row highlighted | Opens `/purchasing` with notice |
| **Sale Invoice** | `/sales?invoice=<inv_no>` & `/print/sale/<sid:int>` | If `invoice` param provided, redirects to `/print/sale/{id}` or shows invoice viewer | Shows notice on `/pos` |
| **Repair Job** | `/repairs?job=<job_no>` | Filters repair jobs table to that ticket | Opens `/repairs` |
| **Software Ticket** | `/software?ticket=<ticket_no>` | Filters software tickets table to that ticket | Opens `/software` |
| **Expense** | `/expenses` | Opens expenses management screen | N/A |

### 2.2 Click-Action Matrix
What happens when a user clicks or presses Enter on a search result depends on the active context:

| Search Location | Entity Selected | Immediate Action Taken |
|---|---|---|
| **Global Search (Ctrl+K)** | Phone Model / Unit | Navigates to `/inventory/models/{product_id}?unit={unit_id}` (opens drawer) |
| **Global Search (Ctrl+K)** | Customer | Navigates to `/credit/customer/{id}` (opens customer khata) |
| **Global Search (Ctrl+K)** | Supplier | Navigates to `/purchasing/supplier/{id}` |
| **Global Search (Ctrl+K)** | Invoice | Opens print preview in new tab: `/print/sale/{id}` |
| **Global Search (Ctrl+K)** | Repair Job | Navigates to `/repairs?job={job_no}` |
| **Global Search (Ctrl+K)** | Software Job | Navigates to `/software?ticket={ticket_no}` |
| **POS Search Dropdown** | Accessory Variant | Adds directly to cart (`addAccessoryCart`) with +1 quantity; plays success beep; clears input |
| **POS Search Dropdown** | Phone Variant (Single Unit in Stock) | Adds that unit directly to cart (`addPhoneUnitToCart`); plays success beep; clears input |
| **POS Search Dropdown** | Phone Variant (Multiple Units in Stock) | Opens quick IMEI Picker modal with available IMEIs for that variant; cashier clicks to select |
| **POS Search Dropdown** | Phone Variant (0 in Stock) | Shows toast notification "Out of Stock" (does not break or add invalid item) |
| **POS Scanner Burst** | Scanned Barcode/IMEI | Bypasses search dropdown entirely; `/api/scan-route` adds unit/accessory or plays error beep |

### 2.3 Search Engine Multi-Tier Ranking (1-Character Instant)
To make 1-character queries lightning-fast and relevant, ranking uses a 4-tier system:

- **Tier 1 (Exact Match)**: Exact Barcode, SKU, full 15-digit IMEI, or IMEI tail ($score = 100$).
- **Tier 2 (Prefix / Starts-With)**: Brand starts with query, Model Name starts with query, Variant RAM/Storage starts with query ($score = 80$).
- **Tier 3 (Word Starts-With)**: Any word inside the name starts with query (e.g. "A15" in "Samsung Galaxy A15") ($score = 60$).
- **Tier 4 (Substring Contains)**: Query appears anywhere inside name, category, or notes ($score = 40$, only evaluated if length $\ge 3$ or if higher tiers yield $< 10$ results).

#### Normalization Rules:
1. Digits: Urdu/Arabic numerals (`۰۱۲۳۴۵۶۷۸۹٠١٢٣٤٥٦٧٨٩` $\to$ `0-9`).
2. Characters: Urdu/Arabic variant letters (`ي/ك/ة/ھ/ؤ/إ/أ/آ` $\to$ `ی/ک/ہ/و/ا`).
3. Wildcard Safety: Escape SQL `%` and `_` using custom `ESCAPE '\\'`.
4. Performance Target: Execution under 30ms on SQLite indexed tables.

### 2.4 Error Handling Contract (404 / 500)
- For API routes (`request.path.startswith("/api/")`):
  Return HTTP JSON:
  ```json
  {
    "success": false,
    "error": "The requested resource was not found: /api/...",
    "code": 404
  }
  ```
- For Browser routes:
  Render a beautifully styled dark-theme HTML page within the app container featuring:
  - Error badge ("404 - Page Not Found" or "500 - Server Error")
  - Friendly explanation message
  - Direct action buttons: "⚡ Return to POS", "📦 Go to Inventory", "📊 Dashboard"
  - Shop footer with "Developed by Ahmed" watermark.
